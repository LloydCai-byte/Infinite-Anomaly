## 实现对应

| 已确认方向 | 本版实现 |
| --- | --- |
| 普通私人住宅；结构一致、整洁舒服 | 原照片的门窗、柜子、厨房与卫生间通路、床、书桌和封闭阳台保留，杂物移除 |
| 分房点击切换 | 七个视角独立切换，未合成不可能的全屋剖面 |
| 物件作为入口 | 入户门启动/查看探索；电脑和随身手机打开应用 |
| 最新规划不设小队与实体异常收藏柜 | 单人接替前一个自己，收集的是经历，旧小队系统正常运行时停用 |
| 出门即回到家，上一人的经历成为记忆 | 出门立刻闪回玄关，代数递增，门面显示正在接收的记忆 |
| 战斗、感知、生存都能推进 | 按出门时能力快照结算；任一门槛通过即可；三条路线各自有文本 |
| 重复记忆吸收经验 | 可吸收重复份，至少留一份；每次结算只发一次奖励 |
| 资源压力 | 储备随游玩时间减少，经验补给，低储备提醒 |
| 唯一结局 | 六段阶段后一个剧情终章，三条成长路线汇入同一结局 |
| 耗尽即失败，不另算剧情结局 | Game Over 停止推进、不保存耗尽状态，恢复最近可用存档 |
| 20 分钟自动存档 | 初始快照、1200 秒周期、保存退出、结局保存、三份备份 |

## 房屋连接

玄关与过厅是同一个入户区域的两个朝向。厨房可由这两个朝向进入，返回过厅。过厅的卧室门进入卧室，卧室转向书桌，书桌旁进入封闭阳台；卫生间从厨房旁的实际门口进入。返回按钮是一种视角操作，不表示新建房门。

不修改用户照片原文件。五张已确认住宅图直接转入项目使用，新增过厅与阳台画面补齐通路。比例和局部细节沿用已接受概念图，不声称建筑测绘精度。

## 可调整的首章配置

首章“末班电梯”包含六段：不存在的一层、反向上升、没有接线的电话、住户确认、墙后的出口、把名字还给它。

数值目前是用于可玩首章的实现值：储备 100，消耗 0.065/秒；补给 3 经验恢复 25；首次记忆 5 经验、重复接收 2、吸收重复份 3；成长成本 3/6/10；单段时长 22–36 秒；连续出门间隔 4 秒。这些不是用户已定稿的长期平衡参数。

完整数百事件、后续世界、长期经济、角色演出仍需后续制作。此版本不把七个家中视角称为七个实际房间。

## 验收

`tools/test.ps1` 在本机 Godot 4.7.1 正常用户环境运行：

- 规则 78 项：结算幂等、快照、三路线通关、首份保护、补给、Game Over、20 分钟保存和校验备份。
- 界面 48 项：房间资源、手机页面、按钮约束、记忆详情、升级、补给、暂停、失败恢复、初始存档恢复开场。
- 两个独立引擎进程 11 项：保存探索中剩余时间；重新启动恢复视角、能力、资源与快照；继续后只结算一次。
- 场景冒烟：七视角、手机四页和门内阅读器实例化无脚本错误。
- 实机鼠标：返回箭头、暂停恢复、手机入口、成长切页和技能购买已验证；原生渲染日志无脚本错误。
- 截图：`.local/home-captures/` 包含七个场景及手机、回忆、失败、结局状态。

测试与截图使用隔离参数，不修改玩家存档。旧存档与旧素材没有被清理。
