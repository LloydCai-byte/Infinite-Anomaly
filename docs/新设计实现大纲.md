# 《无限异常》新设计实现大纲

> **当前实现：** 用户进一步要求现有故事复用三十次、完成剧情以外的全部功能。本轮已按新玩法实现，入口 `scenes/containment/main.tscn`，见[完整功能版实现与验收](完整功能版实现与验收.md)。本文以下阶段安排保留作历史，不能当作当前未完成事项。

> **2026-09-27 后续变更：** 用户已指定[分支调查与异常收容的新玩法](最新玩法基线_2026-09-27.md)。以下阶段 1／2 为已有实现记录，后续阶段仍是旧计划；继续实现前须按新基线调整，不能直接恢复战斗主导或“全金即揭秘”的旧安排。本轮仅对齐设计，没有改动程序。

依据：[当前设计基线](当前设计基线.md)及飞书《故事背景》revision 1832。日期：2026-09-27。

本文是逐阶段实现计划。2026-09-27 用户已确认阶段 1 功能并要求继续，阶段 2 已实现；首次探索保持整屏单幅场景。实际完成状态见阶段验收记录；阶段 3 起仍是计划。

## 实现目标

先交付一个小而完整的测试版，让玩家能实际走完：

**在家开门 → 首次五图探索与选择 → 解决异常、拿到卡 → 派男主自动刷 → 家中陪伴或猫眼看进度 → 每轮收货 → 分解、升级 → 尝试下一故事 → 卡变金、最终闪光封闭。**

最后用占位事件验证“主线完成、全金后开揭秘故事”的流程。三个测试故事足够验证这些系统，不提前编写三十个正式故事。

## 阶段 1：做出能玩的第一个五图故事

**玩家可以做什么：** 从家中点击门进入第一个测试故事，观察五张完整场景画面并作出选择；得到成功或失败结果；返回家中，看到异常卡。

工作内容：

- 核对旧工程可复用的住宅背景、屏幕适配、音量与输入代码；建立新流程入口和独立的新存档命名空间，避免读入旧版剧情状态。
- 首次探索采用数据驱动的故事节点：图片、叙述、说话位置、选择、条件、结果与跳转分别配置。
- 先生成故事一的五张图，以用户最新简练漫画参考校准；对白和选择在 Godot 内排版。
- 一处观察选择、一处能力判定、一条可触发的失败返回路径即可。分支可以共用同一张图并改变气泡或结果，不为短测添加大量专属分支图。
- 放入最小异常卡展示；卡面可先使用故事图中适合的构图制作占位，独立正式卡面以后补。

验收：五张图可完整推进；选项确实改变结果；死亡能回家再挑战；一次结算不重复发卡；鼠标和窗口尺寸变化不破坏交互。

已交付，见 [阶段 1 记录](阶段1实现与验收.md)。

## 阶段 2：接入自动探索、女主陪伴与猫眼

**玩家可以做什么：** 让男主自动探索已解决的异常，留在家中听音乐、看女主活动，随时点击猫眼观察。

- 只有已解决故事可以开始自动刷；自动状态与玩家当前打开的界面分开保存。
- 循环读取同一个故事的五图序列，完成一轮后继续下一轮。首版明确是固定序列占位。
- 猫眼视图固定为左半屏漫画、右半屏女主看猫眼。退出猫眼不会让副本重开或停住。
- 女主先用少量日常动作与状态切换建立陪伴感，再补连续动画；不先制作庞大动画库。
- 加音乐与环境音控制、基础番茄钟；番茄钟是专注工具，不默认要求每隔一段时间回来点击续刷。
- 每轮掉落立即计入家中收货箱，结算依轮次编号防止重复。玩家是否正在看猫眼不影响到账。

验收：在房间间切换、查看卡或离开猫眼时探索正常推进；连续三轮各结算一次；收货不用召回男主；主动暂停的行为明确。

测试实现建议：应用运行时，窗口失焦仍继续刷；真正暂停才停。关闭应用后的离线规则另定，首轮不伪装成已完成离线系统。这是待验证的实现选择，不是从旧版继承的既定规则。

已实现并验证，见 [阶段 2 记录](阶段2实现与验收.md)。本阶段测试轮次为 60 秒；卡册、物件面板、房间切换不暂停；退出只保存当前进度，不计算离线时间。

## 阶段 3：让收货、分解和能力成长真正产生作用

**玩家可以做什么：** 拿出收集品，在家中物件处进行分解，选择提升能力，并在探索中体验变强。

- 物品拥有分解配方，产出多种点数；能力拥有自己的升级消耗，不能全部折叠成同一种通用经验。
- 先用感知、思维、神经等少量能力测试接口；完整维度数量以后补，不承诺本阶段已完成二十维成长。
- 卡牌进度与能力点分开记录：刷本同时推进卡牌修复和产出成长素材，避免将金卡等级直接当人物等级。
- 以同一障碍验证两种解决法：能力普通时需要观察、选择；能力显著超出要求时可强行通过。临时阈值不充当正式数值平衡。
- 收货、分解、升级、卡牌进度采用一致的存档事务，保证退出重开后不会丢掉已确认的进展。
- 死亡保留的正式细节留待决定；测试版必须明确写出暂定保留范围，并验证重复失败不无限领取首次奖励。

验收：玩家能说明一种物品可帮助提升哪种能力；升级前后确实改变至少一个选择结果；分解一次只扣一次物品、只加一次点数；保存退出后可恢复。

## 阶段 4：扩成三个故事，共十五张故事图

只添加十张新故事图，总计三个故事各五张。故事名和情节均为随时可换的测试内容。

| 测试故事 | 五张图的临时顺序 | 主要测试职责 |
| --- | --- | --- |
| 不存在的楼层 | 楼梯口 → 重复楼层 → 门牌线索 → 出口选择 → 返回门前 | 首次探索、观察选择、解锁刷本 |
| 夜班便利店 | 店门 → 货架 → 收银台 → 异常逼近 → 离店 | 高能力强行通过、不同掉落配方 |
| 反着走的钟 | 房间入口 → 倒走的钟 → 线索位置 → 尝试干预 → 稳定后的房间 | 失败后再来、第三张卡、完成主线标记 |

这些名称不绑定六大类别，不补正式角色背景，也不为它们强写世界观解释。所有测试故事都使用同一套节点、判定、挂机和结算系统。

为三个副本配置不同的产出偏向，使玩家可以为想升级的能力选择刷哪个故事。只测试这项决策是否成立，不制造长时间重复劳动。

验收：三个故事全部可进入、选择、完成和重复刷；添加第二、第三个故事主要靠配置和素材；玩家至少能看出两种刷本目标的差别；素材清单明确是十五张故事图。

## 阶段 5：卡牌普通、金色、闪光与组合机制

**玩家可以做什么：** 看见卡牌随重复探索成长；转金后继续刷但收益降低；到闪光后该异常关闭。

- 明确普通、金色、闪光三个状态的视觉与掉落行为。金色不能提前封闭，闪光不能继续产出。
- 转金等级、转闪条件、每轮进度、金色掉率都来自配置。测试时使用较短阈值，不真的挂到示例中的 300 级才验收。
- 闪光表现参考文档附带视频的彩色覆膜反光与转动层次；使用原创卡面和轻量材质效果。
- 漫画数据预留“阶段 → 候选画面 → 兼容条件 → 使用记录”。实际轮次选定的组合保存下来，切换界面不能重新随机。
- 正式多图变体后续补齐；当前用测试配置检查选择和覆盖记录即可。相同五张图的播放不能算作丰富的视觉变体。
- 原文的 960 种是乘法示例，不是每个副本当前都要绘制的任务。未来先过滤不兼容组合，再在有限有效集合内避免重复；覆盖完后按确定的闪光规则处理，不能承诺有限集合无限不重复。

验收：金色掉落低于普通；闪光轮次先结算当前轮，再阻止下一轮并退出自动循环；零掉落和入口关闭一致；组合记录跨保存恢复一致。

尚待定稿：闪光究竟需要组合全覆盖、固定进度还是共同满足。测试配置可以模拟这些边界，但不能用调试规则替代用户最后的决定。

## 阶段 6：跑通终局入口、时间边界与完整体验

- 三个测试故事都首次完成后，标记“测试主线完成”，不再出现新故事；女主给出刷金提示。
- 全部测试卡为金色或更高时，开放占位揭秘事件。已经闪光的卡也满足金色要求，不能因升级而失去终局资格。
- 揭秘事件先复用住宅门的画面与极短占位文本，不追加第十六张故事图，也不在这一步编写正式结局长篇剧情。
- 验证死亡返回、暂停、后台运行、主动退出与存档恢复；断在一轮中途时不重复发奖，不漏掉已完成轮次。
- 再看剧情推进所需的基础能力是否过高，以及纯挂机成长是否真的给出明显优势。调整测试参数后再定正式时长。
- 最终交付一个可启动的测试版本，并明确尚未补齐的正式故事、变体素材、完整能力目录及离线规则。

验收：新存档可完整跑通三个故事、重复探索、收货成长、全金揭秘；可独立验证闪光封闭；不要求全闪光才让玩家看到结局入口；全过程没有旧食物条或旧小队系统意外介入。

## 制作与复用边界

| 分类 | 后续处理 |
| --- | --- |
| 旧住宅素材 | 结构与整洁度符合即可候选复用；画法过精致的需按最新参考改；不自动继承旧点击功能 |
| 旧冒险素材 | 可作开发占位或技术测试；不能据此冒充三个新测试故事的正式十五图已完成 |
| 旧 UI、存档代码 | 可复用通用部分；先检查是否耦合旧属性、补给、任务、暂停和结局规则 |
| 新剧情图片 | 一张完整场景一个素材文件；按故事与顺序编号；保留角色和衣着一致性；字幕独立 |
| 变体素材库 | 留数据接口，等核心体验通过后分批制作；当前不扩量 |
| 女主、音乐、物件 | 服务家中陪伴与实际交互；先最小可用，后补表现；需要制作的单独列清单 |
