# 无限异常 MVP 实现与验收

日期：2026-09-24。依据用户提供的《无限异常 开发规划 v0.1》，使用本机 Godot 4.7.1 实现。用户明确要求先按手册制作 MVP，全部视觉素材使用线框占位；未采用讨论中额外提出的玩法建议。

## 实现范围

固定主神空间、单队自动探索、两项永久能力、处置等级门槛、失败退刷、手动重试、关底自动刷取、旧副本回刷、两种资源、首次收容、重复回响自动解析、按池保底、永久金边结案、三种设施升级、漫画按时间揭示与独立回看、本地保存与备份恢复。

A01 末班电梯按手册的 6 阶段、8 张卡、2 个刷取点、160 秒阶段计时、60 信用点与 20 能量关键升级、第五次保底实现。关底池覆盖全部随机卡。B01 空站来信是 3 阶段、3 张卡的配置扩展占位，不计入正式内容产量。

无移动、寻路、碰撞、手动战斗、装备、多队调度或自由建造。无外部图片资源。卡面、房间与分镜由 GDScript 绘制，中文说明和对白保持可编辑。

## 实际验证

| 验证 | 结果与方法 |
| --- | --- |
| 规则测试 | 369 项检查通过。覆盖确定性首通、能力门槛、升级、受阻退刷、统一结算、重复解析、读取不发奖、随机数恢复、保底与存档校验。 |
| 保底边界 | 100 个确定性随机种子各跑关底 15 轮，均补齐三张随机卡并永久结案；完整池不积攒保底。 |
| 图形交互 | 19 项检查通过。通过 Godot 视口注入鼠标与键盘事件，点击开场、派遣、卡册、升级、重试、开发推进和结案按钮，走完收容循环。 |
| 后台运行 | 图形版本实际最小化 1.2 秒，验证剩余计时继续减少。 |
| 跨进程恢复 | 第一进程保存阶段 2 剩余 17.5 秒状态；第二进程读取后保持剩余时间、20 信用点。继续结算后为 40 信用点，无离线补发、无重复首通。 |
| 保存失败 | 使用无法创建的隔离测试路径，验证购买失败时恢复原资源和设施等级，并暂停运行。 |
| 损坏恢复 | 故意损坏测试主存档，校验能够识别损坏，最近备份仍可恢复。未触碰玩家存档。 |
| 画面检查 | 实际渲染开场、主空间、任务、卡册、设施、漫画、卡牌详情与结案页面；修复进度条与文字重叠。13 个界面完成运行冒烟检查。 |
| 最终日志 | 最终规则、图形交互、截图、存档往返日志中无 ERROR、WARNING 或 FAIL。 |

机器结果保存在 `.local/test_report.json`、`.local/ui_test_report.json`。详细日志位于同目录的 `tests.log`、`ui_tests_graphical.log`、`session_save.log`、`session_restore.log`、`capture.log`。截图同样位于 `.local`，不属于正式美术。

## 当前边界

完成的是可玩的线框 MVP。正式漫画与美术、音效、内容量与节奏调优仍待后续制作和实际游玩反馈。关闭进程后的离线收益按手册保留为未启用功能，界面有明确提示；T12 离线补算验收不适用于当前版本。

手册未规定具体值的设施参数采用可配置起点：生活空间 80 信用点，收容展示 80 信用点与 25 能量，展示升级将未来结案的信用点奖励提高 20%。主线关键门槛、奖励、掉落池和保底沿用原方案。

当前启动依赖本机已安装的 Godot，提供 `启动游戏.cmd`，尚未导出独立发行程序。存档位于工程下 `.local`，适合本地可写目录；发布前需要落实发行包、正式存档目录、多实例保护和平台设置。
