## 龙崖：整备场景承接小队成长

官方介绍明确自动行动与可施放战法并存，装备、技能与城镇成长都很丰富。截图中，城镇背景和底部主导航跨多个整备面板保留；“冒险”入口突出。冒险者界面组织角色列表、当前角色与装备、仓库；设施界面围绕招募、制造、研究等具体任务展开。战斗截图则把队员身份和状态固定在底部。

观察证据：[角色整备](reference-research-2026-09-27/dragon-cliff-0.jpg)、[酒馆](reference-research-2026-09-27/dragon-cliff-3.jpg)、[学院](reference-research-2026-09-27/dragon-cliff-11.jpg)、[战斗](reference-research-2026-09-27/dragon-cliff-13.jpg)。这些是官方宣传截图，不代表本轮操作验证。

对本项目的建议：

1. 第一阶段把基地作为稳定的整备场景。点击队员或设施时，在场景上展开详情，保留当前位置与资源上下文。
2. 让升级围绕“当前等级、下一次收益、花费、能否操作”四项展开。队员的体质、防具、武器、能力是当前需求；不从参考自动添加居民经营、舰船探索、附魔重铸等系统。
3. 小队出战后，仍保留每名队员的身份与状态，便于形成对具体人物的记忆；基地升级依用户规则需召回后执行。
4. 主要迁移“设施支撑队员→出战取得资源→回来继续成长”的关系。参考游戏的复杂装备构筑与用户希望的直接升级体验有明显距离，需主动缩减认知负担。

## 守城英雄传：稳定操作区与即时成长反馈

图一可直接看到：顶部为城堡 HP／MP 与波次，主体为城堡和战场，底部约占画面五分之一，集中放等级资源、城堡升级、开始战斗和各类功能入口。金属边框和按钮形态把这些控件组织成完整的一条操作区。

官方战斗截图补充了另一种状态：底部左侧变成各单位伤害贡献，中间为结束战斗、自动和倍速，右侧为技能入口。英雄管理截图呈现右侧角色列表、左侧选中角色的全身形象、属性、技能和操作。

观察证据：[战斗状态](reference-research-2026-09-27/defenders-0.jpg)、[英雄管理](reference-research-2026-09-27/defenders-2.jpg)。官方说明支持英雄、炮塔和城堡成长；仅凭静态截图不能断言所有整备操作在战斗中都可执行。

对本项目的建议：

- 第二阶段保留“大部分屏幕看战争，底部集中处理成长”的结构，给基地、兵员和全军强化留下固定入口。
- 底部是相同位置、随状态变化的工作区：第一阶段整备时升级，出战时看状态与召回；第二阶段处理全军成长。不要因为参考有升级入口，就破坏第一阶段“召回才可升级”的规则。
- 详情可以在底栏上方展开，结束操作后仍回到原战场位置；这是设计建议，未作为参考游戏实测行为。
- 大规模战斗不能让伤害数字完全淹没角色。可优先显示关键伤害和军团贡献，具体显示规则待原型验证。

## 全军出鸡：空间、接敌和局部反馈

用户图二可见两侧小队以纵向队列分开站在同一片斜俯视沙地，顶部有双方名称、绿色条、数字、倒计时与暂停／倍速标志。中央大面积留给战场，地图边缘的岩石、仙人掌等用于界定空间。

图三可见双方集中交战，单位头顶出现局部血条和伤害数字，地面阴影与特效帮助辨认单位位置。两张截图不能证明寻路算法、碰撞规则、自动接敌的时序，顶部数字具体代表人数还是另一种状态也没有文字证据。

对本项目的建议：

- 第二阶段采用有纵深的战斗场地，保留从出兵、行进到交战的空间关系。
- 早期画面有较大空地可以成立，但后期的规模感要通过更多编队、更密的交战区域和更强的火力反馈形成；不能只把早期几名士兵缩小、背景放大。
- 前期重在辨认个体动作和小队成员，后期重在看清军团阵型、前线位置和兵种差别。角色数量增多后，信息显示需要相应变化。
- 用户引用的是战场和 UI 方向，参考截图的像素风不自动改变其录音中倾向高清表现的要求。

## 星际酒馆：把成长变成可见的部队变化

指定视频的公开章节为：00:00 进入酒馆与模式；01:06 资源和升级；03:31 人族词条；06:00 虫族词条；07:20 神族词条；08:55 原始虫群与塔达林；10:12 定点部署；11:08 结尾。

关键帧能看到卡牌选择、带编号的编队区域和大量战斗单位，讲解中出现快速生产、孵化、虫卵、能量、集结、折跃、定点部署等。多个画面中，卡牌说明与其对应的一组实际单位同屏出现，后段示例包含密集单位和不同火力特效。

补充卡牌资料：[SC Pub 社区 Wiki](https://neko-para.github.io/scpubwiki/)。此为社区资料，版本时效有限，仅辅助理解“一张卡可以承载多个单位、生产效果改变兵力”的结构，不照搬数值或宣称为当前正式版本规则。

对本项目的建议：

1. 第二阶段每次成长尽量能看见后果，例如编队人数、武器表现或火力变化，而不只更新一个综合战力数字。这是设计方向，具体升级项待确定。
2. 学习“少量管理对象对应很多作战单位”的表达，让玩家管理基地和军团，同时看到真实单位在战斗。
3. 收集卡与指挥对象应先分清。当前录音中的异常卡、文明卡承担收集与进度；用户没有因此授权将它们改成抽卡购买的兵种卡。
4. 不因研究此游戏自动加入多人对局、限时商店刷新、三连、随机抽卡或复杂种族羁绊。它在本项目中首先服务于军团表现与成长反馈。

## 两阶段的建议衔接

| 维度 | 第一阶段 | 第二阶段 |
| --- | --- | --- |
| 玩家主要关心 | 这几名队员如何变强、能否完成任务 | 基地能输送怎样的军团、能否攻克下一颗星球 |
| 整备对象 | 房间设施与具体队员 | 多个基地、兵员培养和全军成长 |
| 主要观看内容 | 可辨认个人的小队战斗 | 开阔、有纵深、规模扩大的军团战争 |
| 成长反馈 | 队员战力、装备和能力的变化 | 编队与火力变化、推进与战损 |
| 收集记录 | 异常／训练任务卡 | 文明卡 |
| 主要参考 | 龙崖的整备与小队结构 | 守城英雄传的操作区，加全军出鸡与星际酒馆的战场表达 |

后续设计应先明确“点击升级后玩家在下一场战斗中具体看见什么变化”，再确定按钮和数值。游戏仍是用户确定的两阶段挂机成长方向，以上研究没有新增正式功能，也没有启动新版本实现。
