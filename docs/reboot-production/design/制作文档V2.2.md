## 游戏到底是什么

一句话：你起初以为自己是通过监控管理四名战士的幕后指挥者，后来发现自己就是这座房间；你先把普通人训练成战士，再接管成群的房间，把士兵不断送入真实的星际战争。游戏由“房间里的小队养成”变成“战场下方经营基地群”的两阶段数值挂机游戏。

|---|---|---|

| 战争入门 | P01演示原房间送下首批四人后空载返回，再培养/运送第二批；先后两批战士独立作战。 | 征服P01得到文明卡；P02开始自行处理产能和伤亡。 |

| 终局与继续 | P12后播放主线结局，人类掌握战略文明网络。 | 返回战争驻防或历史训练补钻卡；一个主线结局，没有隐藏真结局门槛。 |

首版节奏目标为第一阶段约2—4小时、完整主线约8—12小时有效游戏时间。这是待实测的设计目标，不是已验证时长。1倍与2倍速共用游戏内时间与收益，2倍同时加快伤亡、生产、训练和技能。章节间没有强制现实时间等待。

## 第一阶段：训练小队规则

### 一次任务如何开始和结束

MVP暂用三波：两波普通敌人、一波首领。正式任务不固定三波，使用waves列表、阶段目标和完成条件驱动。开始前四人满生命，波间仅存活者恢复；倒下者本次任务不归队。run_id唯一；MVP波1/2/3权重暂为20%/20%/60%，正式版使用每波reward_weight并校验总和100%。已完成波次独立入账，合金余数在最后一个完成节点补齐。首胜配方和卡进度只在该任务所有目标完成时发放，不能写if wave==3。

召回放弃当前未完成波次，保留已完成波奖励，四人免费恢复。全灭同理，自动重复和自动下一关都停止，避免不断失败却不知道。胜利可返程、重复本任务或进入下一关；重复前在幕后完成训练复位，四人齐全后再开下一局。没有体力、没有复活付费，也没有由死亡扣除等级的惩罚。

在外出战时：体质、武器升级、换装、能力学习、打印、设施升级、批量训练全部不能提交。界面可以查看，并直接提供“召回小队”入口。召回确认后回到原来想升级的页面，减少来回找按钮。第二阶段的基地经营允许在战斗中执行，属于明确不同的管理规则。

### 自动战斗怎么表现、怎么算

采用固定高清背景加独立单位序列帧。单位在二维地面坐标上移动，视觉为斜俯视；近战走到射程、远程在射程内站定。攻击动画不因受击中断；伤害触发点由数据时间决定，不能靠动画帧率决定。受击只做颜色闪白、小幅血液、数字和音效。死亡完成一次倒地动作后移除战斗碰撞，尸体淡出。

| 规则 | 第一版定义 |
|---|---|
| 目标选择 | 优先可攻击的敌方治疗者，其次最近目标；同距离按稳定单位ID选，避免每帧换目标。前排通过更靠前的出生位置承担伤害，不添加复杂仇恨系统。 |
| 寻路范围 | 开放战斗平面，只绕行不可走的场景边界；不做地图探索或复杂迷宫。背景装饰不能阻塞主战线。 |
| 近战范围 | 标准48逻辑像素；远程360逻辑像素；世界坐标按1600×900参考分辨率标定，分辨率变化不改变逻辑距离。 |
| 伤害 | 单次伤害=max(1, round(攻击×技能倍率×100/(100+护甲)))。不做暴击、命中与闪避随机。 |
| 技能 | 固定冷却自动施放；范围技能最多命中6目标；同源护盾只保留最大值。治疗优先生命比例最低的存活友军。 |
| 无硬直 | 受到伤害不重置攻击计时、不中断技能、不推退；死亡才终止动作。 |
| 波间处理 | 清空弹道和短期增益；幸存者满血；等待2秒展示波次，再生成下一波。 |
| 自动逻辑 | 重复刷卡时停在选定关；自动下一关按序前进到M10，失败停止；设置不偷偷改成另一种。 |

### 战力、关卡敌人与第一次调参

战力仅为提示，不参与实际伤害。单人战力=round(生命/10 + 每秒普攻伤害×3 + 护甲×2 + 每秒治疗量×2 + 能力等级合计×15)，队伍为四人相加。公式只求能解释成长，不能保证不同编制在每个关卡相同胜率；UI注明“参考战力，敌人类型仍影响表现”。UI图片中的数值是说明布局的示例快照，最终由数据表和公式实时生成，不应硬编码图片数字。

以下仅为MVP三波测试数据：M01小怪生命70/攻击8/护甲0/间隔1.4秒；首领450/18/5/1.6秒；4小怪→6小怪→首领+2小怪。任务系数=参考战力/280，生命乘系数，攻击乘系数的0.75次方；小怪护甲=5×(关卡序号−1)，首领再加5。MVP后续普通波6/8人，第三波首领+4随从。正式任务重新编排可变长度的波次、敌军批次、阶段目标与奖励权重；不能只把MVP第三波反复复制。

算例：基础乔越22攻击对5护甲敌人，伤害round(22×100/105)=21；升级一级体质后基础攻击增0.66，UI显示约23，内部保留小数，在结算伤害时取整。全队基础普攻每秒约79点，M01的总敌方生命约1290，因此纯输出下限约16秒；计入跑动、选目标和波间过渡，目标完整任务时长45—75秒。首次验证发现相差过大时优先调敌人生命和出兵节奏，不通过隐藏伤害修正欺骗玩家。

MVP经济试算按10关、每关8次胜利估算：80次完整通关，若每局45—90秒则纯战斗60—120分钟。这个估算只适用于MVP三波测试，不作为正式版时长承诺；正式版按各任务实际战斗段、回房成长与刷卡目标重测。金卡/钻卡不加战力，钻卡为额外收集目标。

## 第二阶段：基地群、真实伤亡与星际战争

### 转阶段的保留与变化

原四人保留各自身份、体质、装备和能力，成为第一批真正投送到前线的战士，既不是教官，也不只是被转换成兵种模板。放下后他们独立参战，使用与后来新人相同的永久伤亡规则；死者进入阵亡记录，房间不会复活或复制他们。原房间继续存在，空载返程后接收并培养下一批4名新人，再次运到战场。房间是持续运转的培养与运输载体，具体战士是一批批会消耗的战斗人员。

战争的补给/科研与训练积分/合金分别保存，不能互换。进入第二阶段时原四人作为首批战士迁移一次；500补给可作为首版测试初始资源，不再额外凭空发200人替代首批。接入百万房间网络后，其他房间各自按培养/运输状态继续投送。历史训练回放仅为档案模拟，不能复活真实已阵亡人员，也不能清除战争伤亡。

### 一场战争的明确规则

正式战役阶段数、敌军批次和结束目标按PlanetDef配置，不固定为三波或五波；原5波仅可保留为早期战争样例。实际补员发生于房间抵达并卸下该批4人时。培养完成不等于立即出现在战场；满载去程、四人下车、空房返程都有独立状态。前一批仍活着不阻止同一房间送来下一批。画面最多呈现我方60/敌方60个详细实例，百万房间及其部队以队伍、运输批次和战区统计汇总，实例上限不得冒充全军总数。

玩家战区耐久初始1000。敌人穿过左边撤离线，每名每秒造成10点耐久伤害，直到被击杀；耐久为0判战败。士兵生命耗尽从前线删除并累计永久伤亡；没有波间全员回满血，幸存者携带现有生命进入下一波，医疗单位负责恢复。波间仅恢复基地耐久50，上限1000。整场征服后幸存者进入驻防并在10秒内治疗至满；这个驻防恢复不复活死者。

前线没有存活士兵时展示下一批在途房间的到达时间；房间仍按各自培养和运输循环工作，不以全军阵亡作为下一批开工条件。若某个房间已满载，则等待航线容量后出发；它不能一边满载在途一边开始培养下一批。关掉自动投送只让完成培养的房间等待，不删除任何人。主动战场撤退另行把幸存者撤到集结区；日常空房返航不携带已经部署的战士。

胜利条件由当前星球战役配置决定，奖励按阶段权重入账；撤退与失败保留已完成阶段收益。失败回上一已占领战区安全驻防，P01失败回轨道安全区，暂停自动进攻。在途房间改投安全集结区并保留当前批次身份，不把他们再生成一次。基础培养与往返渠道继续运行，资源为0也能逐批培养并运来新人；驻防被动收益仍是待测试的经济建议。

## 剧情、人物与已确认的漫画平涂美术规范

### 已选方向与原创角色制作标准

视觉依据见文首对比图左侧A。用户选择的是漫画平涂的整体方向，不是批准把示例人物直接当成四人的最终定稿。原四人重装风格板撤下，角色身份与职业设定保留，外形按此处规范重绘。原主场景图同样不再用作材质与光影依据。

采用高清2D漫画线稿加平涂：明确、干净的外轮廓，内部结构线更轻；每种主要材质以一块底色加一档主要硬边阴影为起点。保留《杀戮都市》方向的正常成人比例、普通人的面孔与不安表情，不做精英军人模板。角色以黑灰衣服和少量功能装备为主，靠脸型、年龄、体态、衣领袖口和武器轮廓区分；减少小零件、复杂绑带、金属反光、渐变和发光装饰。人物、装备和怪物均为原创。

四人的立绘、战场小人和动作必须共享比例、线粗、色板、阴影方向与武器结构。职业识别以乔越的盾、周霁的步枪、林衡的重武器、贺维的医包为主，辅以少量实色标识；不能靠满身灯带区分。先验收一名角色的站立、跑动、攻击在实际游戏尺寸下的清晰度，再扩展四人。对比图中仍有柔和明暗的部分只是示意，正式资产继续收敛色阶；不得把独立生成图直接拼成一套动画。

## 全局 UI 设计规范

UI配合漫画平涂采用简单深灰面板、规整文字与清楚的状态色；青色可操作、暖金奖励、红色损失，取消金属质感、泛蓝光和多层装饰边框。已有UI线框图保留布局与交互作用，不要求把线框颜色原样复制成成品。前期基地主画面约占80%；战斗顶栏约10%、底栏约16%；后期经营抽屉不超过55%，保留可见战场。

## 制作人员怎么开工：工程与数据结构

本次文档是新版本设计，不修改现有发行包。新实现建议放在独立目录scenes/reboot、scripts/reboot、assets/reboot；验证完成前不改根启动脚本。旧containment/continuity/campaign工程、发行包和存档保留为历史，不自动导入新玩法。游戏引擎沿用本机已经安装的Godot，正式打包前固定经过项目验证的版本，不因这次文档自行升级工具链。

### 程序模块与场景树职责

| 模块 / 场景 | 负责什么 | 不得承担什么 |
|---|---|---|

### 存档格式与不可丢的字段

存档保留基础字段及训练数据；war新增原四人的真实unit_id与存亡状态、room_group_id、房间各循环状态数量、独立首房room_id、当前cohort_id、当前4人身份、到达队列、去/返程剩余时间、已交付cohort记录、在途/前线/集结区分职业人数、阵亡和战报。百万房间用群组状态桶和事件队列汇总，不保存一百万套动画对象。原四人保留可追溯记录；阵亡不可被重新培养或读档领取逻辑覆盖。任务保存可变长波进度与奖励权重，升级正式内容不依赖总波数为3。

提交顺序：验证当前状态与余额→构造内存事务→写临时存档并校验→原子替换主档并保留备份→显示成功。保存失败回滚内存事务并保持按钮可重试，不能一边说失败一边扣钱。转阶段保留毕业前快照；同一run_id与奖励编号具有幂等性。版本迁移仅支持明确测试过的前一个新版schema，旧游戏数据放在独立命名空间。

### 性能预算与可扩展性

首版详细表现实例目标120（我方60、敌方60），它只是渲染与局部战斗表现预算。用户明确的100万个房间网络通过分组模拟、四人投送批次和战区聚合表现；不得据此写成世界只有60名士兵。房间视觉至少显示满载到达、四人下车、空房离场三段；数据层持续跟踪未绘制的运输批次及各战区兵力，不因隐藏精灵取消战力或伤亡。该规模的聚合模拟需要先做压力与守恒验证。

暂定性能目标：1080p、120战斗单位时中端目标机稳定60fps；最低目标机保底30fps；首次进入任务≤5秒，后续预载切换≤2秒，内存预算≤2GB。上述均需选定具体测试机器验证，当前没有声称已达到。优先测满单位、满技能与2倍速叠加，不只测空场景。

## 制作风险与本次建议的边界

| 风险 | 本版处理 | 何时必须重新评估 |
|---|---|---|
| 序列帧质量和成本 | 先做A小样；不预承诺一键生成全动作。 | 角色武器变形或每组动作修复超过人工制作成本。 |
| 刷金卡重复感 | 8胜作为起始值；新关、新配方、角色对白穿插；钻卡可选。 | 两次试玩连续反馈“只是在等毕业”，下调金卡次数或提前解锁新任务。 |
| 永久伤亡造成卡死 | 免费基础产能、安全驻防、旧星球稳定收益。 | 恢复再挑战超过5分钟无操作等待，则提高恢复产能。 |
| 后半段只是前半段放大 | 生产、编制、科技和永久损耗同时成立，战时可经营。 | 玩家只点一个升级而不看兵种，需调整敌阵差异而非堆新货币。 |
