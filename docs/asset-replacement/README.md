## 后续操作

1. 用固定素材编号定位行和目标资源；保留原文件及SHA256。
2. 新图片按规格制作。开场、房间、人物房间整图为1920×1080。人物房间图须整张绘制，不能用立绘贴到空景上。
3. 普通图片可以运行 `tools/asset_tracker.py replace --id <编号> --file <候选绝对路径> --version <版本号>`；旧文件和清单会备份到 `art/asset-replacement-history/`。此工具只做本地操作；落盘后仍须引擎导入和实机检查，未测试的变更不提交用户验收。
4. 战士/异常动作使用SpriteFrames、图集和motion.json成套导入。75条战士动作逐条检查，不能因为容器文件存在就把5个动作全勾选。现有视频导入工具为 `tools/import_earth_actions.py`，不触发未经确认的付费生成。
5. 整图人物热区坐标（1600×900的UI坐标）放 `assets/earth/home/home_hotspots.json`，按整图ID和人物ID记录 `[x,y,w,h]`；缺图时出现明确姓名交互标记，有整图后隐藏标记、启用对应矩形热区。
6. 运行 `tools/asset_tracker.py audit` 刷新本地JSON、CSV和HTML；执行Godot资源检查、受影响功能检查、重新打包，然后记录替换版本。自动检查不会将用户验收改成已通过。
7. 只有用户明确要求同步飞书时才写入远端。不要批量创建重复记录；使用 `record-id-map.json` 按素材编号更新已有行。原图附件上传本轮被自动审批拒绝，表内使用本地文件路径；未经新增授权不重试上传。
